# ОПОРА — официальный лендинг (концепция № 4 «Современный объект»)

Готовый исходный проект для публикации через **GitHub → Vercel**. HTML/CSS/JavaScript, без сборщика, npm-пакетов и платных интерфейсных библиотек. Серверная функция `/api/submit-lead` предназначена для отправки заявок через Resend.

**Основной принцип:** все открытые файлы сайта можно хранить в публичном репозитории, но секреты и почтовый адрес получателя никогда не добавляются в код или GitHub.

## 1. Что загружать в GitHub

Содержимое **этой папки**, включая скрытый `.gitignore`, должно оказаться **в корне репозитория** (не загружайте родительский ZIP как один файл). Обязательно нужны:

```text
index.html                  Главная страница
privacy.html                Страница политики персональных данных
styles.css                  Оформление, включая мобильную версию
main.js                     Меню, FAQ и логика формы
config.js                   Публичный URL обработчика (без секретов)
assets/                     Все изображения, иконка и OG-обложка
api/submit-lead.mjs         Серверная функция на Vercel
vercel.json                 Настройки Vercel
package.json                Настройки Node.js и тесты
robots.txt                  Правила для поисковых роботов
.env.example                Перечень параметров (без значений)
.gitignore                  Не позволяет случайно выгрузить секреты
```

Файлы из `docs/` и `tests/` полезны для сопровождения, но не являются публичными страницами сайта.

### Нужен ли формат WebP для GitHub?

**Нет.** GitHub и Vercel принимают изображения `JPG`, `PNG`, `WebP`, `SVG` и другие форматы. Здесь фотографии уже оптимизированы в **WebP** для ускорения загрузки, а OG-обложка — в JPG для совместимости с предпросмотром ссылок. Хранить исходные многомегабайтные PNG в репозитории необязательно.

## 2. Размещение на GitHub

1. Войдите в GitHub и создайте новый репозиторий, например `opora-site`.
2. На первом этапе выберите **Private**; позже, если нужно, можно поменять на Public. Публичность кода не нужна для работы Vercel.
3. Откройте **Add file → Upload files** и перенесите всё содержимое проектной папки (в веб-интерфейсе удобнее добавлять папку `assets` и `api` перетаскиванием). Папки должны сохранить свои названия.
4. Нажмите **Commit changes**. Проверьте, что `index.html`, `vercel.json` и `api/` находятся в корне.
5. **Никогда не добавляйте** файл `.env`, реальные почтовые адреса получателя, пароли и API-ключи в коммиты.

Альтернатива для компьютера с Git: `git init`, `git add .`, `git commit`, подключение remote и `git push -u origin main`.

## 3. Подключение Vercel

1. Войдите в <https://vercel.com> через GitHub.
2. Нажмите **Add New → Project** и импортируйте репозиторий `opora-site`.
3. Укажите **Framework Preset → Other**, **Root Directory → `./`**.
4. Для статического HTML **Build Command оставьте пустым** (Override → пусто). Output Directory по умолчанию (`.`); отдельного `dist` здесь нет.
5. Создайте проект кнопкой **Deploy**. Страницы и фотографии появятся сразу. Серверная форма начнёт реально отправлять письма **только после выполнения следующего пункта**.
6. При последующих коммитах в GitHub Vercel автоматически создаст новую сборку.

## 4. Отправка заявок с формы на Gmail

В этом проекте серверная функция отправляет заявку **не через почтовый клиент посетителя**, а напрямую через почтовый API. Письмо содержит имя, телефон, город, необязательный тип вопроса и описание ситуации.

1. Создайте аккаунт в [Resend](https://resend.com/).
2. Добавьте домен, с которого будут отправляться письма, и подтвердите его: Resend покажет требуемые DNS-записи (обычно SPF/DKIM). **Gmail как адрес получателя подтверждать не требуется**, но домен отправителя должен быть разрешён сервисом.
3. Создайте **Resend API key**.
4. В Vercel откройте **Project → Settings → Environment Variables** и добавьте:

   | Имя переменной | Что указывать |
   |---|---|
   | `RESEND_API_KEY` | Секретный API-ключ Resend |
   | `OPORA_MAIL_TO` | Ваш адрес Gmail для уведомлений |
   | `OPORA_MAIL_FROM` | Подтверждённый адрес отправителя вашего домена, например `ОПОРА <forms@ваш-домен.ru>` |

   Используйте окружение **Production**; при необходимости добавьте Preview для тестов. В исходном коде этих значений нет.
5. Нажмите **Redeploy** после добавления переменных.
6. Откройте ваш Vercel URL, заполните форму и убедитесь, что письмо **поступило** в реальный почтовый ящик, включая проверку папки «Спам». Успех API означает принятие письма провайдером, а не подтверждённую доставку в Gmail.
7. Если ссылка формы выдаёт ошибку — проверьте **Vercel → Logs/Functions**, состояние домена и API-ключ Resend.

В поле **«Тип вопроса»** вариант **«Выберите при желании»** сохранён, это **необязательное** поле. Телефон для звонков на сайте: +7 (928) 126-88-32.

Сайт не показывает адрес Gmail получателя, и этот адрес не включён ни в публичный HTML, ни в `main.js`, ни в `config.js`, ни в `api`.

## 5. Домен и поисковая индексация

До покупки домена сайт работает по адресу вида `название-проекта.vercel.app`. После подключения вашего домена в **Vercel → Settings → Domains** проверьте:

- добавить в `<head>` главной страницы абсолютный `canonical` и `og:url`;
- заменить `og:image` на полный URL изображения, например `https://ВАШ-ДОМЕН/assets/og-cover.jpg`;
- скопировать `docs/sitemap.template.xml` в корень как `sitemap.xml` и указать настоящий адрес сайта;
- добавить ссылку `Sitemap: https://ВАШ-ДОМЕН/sitemap.xml` в `robots.txt`;
- проверить сайт в Яндекс Вебмастере / Google Search Console, если эти сервисы используются.

**Текущий `og:image` указан относительным путём:** для некоторых соцсетей/мессенджеров перед публичной индексацией потребуется заменить его на абсолютный.

## 6. Персональные данные: важное условие публикации

Форма собирает имя, телефон и описание ситуации — это персональные данные. Страница `privacy.html` представляет собой **редакционный шаблон политики**; до запуска на коммерческий трафик нужно указать реального оператора данных, подтвердить законные основания, сроки хранения и порядок обработки. Подключить заявочный API только после проверки соответствия закону.

**Для граждан Российской Федерации особо важно:** актуальная редакция ст. 18 ч. 5 закона 152-ФЗ устанавливает ограничения на использование баз данных за пределами РФ при первичном сборе данных. Схема с иностранными сервисами Vercel/Resend/Gmail **не должна считаться автоматически соответствующей** требованиям локализации и трансграничной передачи. Для целевой аудитории в России оцените с юристом размещение приёма заявок на инфраструктуре РФ с последующей надлежащей обработкой уведомлений. В зависимости от выбранной схемы может потребоваться заменить `/api/submit-lead` на интеграцию с российским сервисом/сервером. См. `docs/PRE-LAUNCH-CHECKLIST.md`.

До настройки API и необходимого правового оформления можно публиковать информационный сайт и использовать указанный на нём телефон, но **не обещайте, что форма отправляет обращения, пока не прошёл живой тест**.

## 7. Проверка и дальнейшее сопровождение

- `node --test tests/*.test.mjs` — проверки серверного обработчика без реальных писем.
- HTML/CSS не требуют сборки, достаточно загрузки файлов.
- При замене фотографий сохраняйте формат WebP, размеры/названия файлов или обновляйте пути в HTML/CSS.
- В дизайне используются иллюстративные изображения архитектуры; они **не представлены как реально выполненные исследования**.
- Подробный чек-лист: `docs/PRE-LAUNCH-CHECKLIST.md`.
