# ОПОРА: как обновить опубликованный сайт

Эта версия подготовлена как **обновление существующего проекта** `opora-expert.vercel.app`, а не как новый проект.

## 1. GitHub

1. Распакуйте архив на компьютере.
2. Откройте GitHub и существующий репозиторий, который уже связан с Vercel.
3. Замените файлы в **корне репозитория** на содержимое папки проекта. Важно, чтобы `index.html`, `styles.css`, `main.js`, `vercel.json` и папки `assets/`, `api/` остались на прежних путях.
4. Сделайте Commit в ту ветку, которую Vercel использует для Production (обычно `main`). Если загружаете через веб-интерфейс, проверьте, что новые файлы действительно **заменили старые** (не создалась вложенная папка).
5. Не загружайте `.env` и секреты API в репозиторий. `.env.example` безопасен: он без значений.

## 2. Vercel

1. Зайдите в существующий проект Vercel, подключённый к этому репозиторию.
2. Откройте Deployments. После коммита должна появиться новая публикация.
3. На Production откройте реальный URL сайта и очистите кэш страницы в браузере при необходимости.
4. Если проект закрыт Vercel Deployment Protection, проверьте Settings → Deployment Protection: доступность для посетителей управляется там, а не HTML-кодом.
5. Проверяйте сайт на телефоне, особенно Hero, стрелки на карточках и нижнюю панель.

**Новый Vercel-проект создавать не требуется.** Если нужно настроить впервые: Framework Preset = Other, Root Directory = `.`, без отдельной сборки (файлы в корне).

## 3. Отправка обращений

Серверный обработчик находится по `/api/submit-lead` и работает на Vercel.

В Settings → Environment Variables нужны:

- `RESEND_API_KEY` — секретный ключ сервиса отправки.
- `OPORA_MAIL_TO` — закрытый почтовый ящик для получения уведомлений.
- `OPORA_MAIL_FROM` — адрес отправителя на подтверждённом домене.
- `OPORA_ALLOWED_ORIGINS` — необязательная строка с дополнительными разрешёнными HTTPS-origin, если это необходимо для проверки.

**Получатель не задан в коде проекта.** После изменения переменных сред выполните Redeploy. Тестируйте настоящую отправку: должно появиться подтверждение на сайте, а письмо должно действительно поступить в ящик. Тесты кода не гарантируют работу доставки без настройки Resend.

## 4. Перед публикацией для клиентов

- Подтвердите юридически корректное описание лица, которое оказывает услуги, и оформите политику обработки персональных данных.
- Оцените соответствие Vercel/Resend/почтовой инфраструктуры требованиям к обработке персональных данных заявителей из РФ, включая требования к локализации и трансграничной передаче.
- Убедитесь, что иллюстративные архитектурные изображения не выдаются за настоящие выполненные экспертизы.
- После получения основного домена добавьте абсолютный canonical и полный URL OG-изображения; настройте `sitemap.xml`.

## 5. Что обновлено в дизайне

- Вместо Unicode `↗` везде применён одинаковый SVG с линиями под 45° (цвет наследует дизайн кнопки или карточки).
- Номера `01 / 06` удалены **только с карточек проблем**.
- Устранены пересечения фотографии и текста на мобильном Hero, а также лишняя подпись на фото.
- Мобильная нижняя панель стала компактнее и не закрывает форму обращения.
- Фотографии WebP, утверждённый дизайн № 4, основные тексты, номер телефона и необязательный «Тип вопроса» сохранены.
